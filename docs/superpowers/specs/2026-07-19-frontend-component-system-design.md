# Frontend Component System Design

日期：2026-07-19

状态：已获用户确认，待实现

## 背景

控制台已经有 `ConsolePageShell`、分页工具栏、列表状态、状态徽章和
`DataTable` 等公共组件，但页面迁移不完整。部分操作页仍然手写表格、卡片、
详情面板和表单反馈，导致间距、边框、空状态、错误重试和可访问性行为不一致。

## 目标

- 将所有控制台页面统一到页面壳、数据展示、表单和详情四层组件体系。
- 保留现有 API、业务行为、路由和视觉主题，不引入新的 UI 框架。
- 让页面模块只负责请求编排、业务字段定义和页面特有交互。
- 让认证、请求 URL、分页、加载/错误/空状态和通用反馈由共享基础设施负责。
- 通过组件契约测试和页面回归测试锁定统一行为。

## 非目标

- 不重写后端 API 或领域逻辑。
- 不改变现有权限、数据格式、路由路径或业务状态含义。
- 不为了组件化引入大型第三方设计系统。
- 不在本轮调整产品主色、字体或整体视觉主题。

## 组件分层

### 页面布局层

`components/layout` 提供：

- `ConsolePageShell`：统一页面宽度、标题、说明和页面级操作。
- `SectionHeader`：统一区块标题、说明和区块操作。
- 设置目录与标签页：统一桌面导航和移动端选择器。组件放在
  `components/layout`，设置注册表和路由解析仍由 `features/system` 提供。

`ConsoleLayout` 暂时保留为兼容别名，所有页面迁移完成后改为直接引用
`ConsolePageShell`，再删除无必要的兼容名称。

### 数据展示层

`components/data` 提供：

- `DataTable<Row>`：列定义、行键、空行和响应式溢出边界。
- `PaginatedListControls`：搜索、分页、加载、失败重试和空状态组合。
- `PaginationToolbar`、`FilterBar`：统一搜索和分页交互。
- `StatusBadge`：统一健康、候选、排队、失败和未知状态的语义样式。
- `LoadingState`、`ErrorState`、`EmptyState`：统一列表状态和可访问性文本。

### 表单与详情层

新增或整理以下低耦合组件：

- `FormField`：标签、帮助文本、输入控件和字段级错误的布局约定。
- `FormActions`：保存、取消、重试等操作的统一排列和禁用状态。
- `DetailPanel`：选中对象详情、键值信息、空选择和加载状态。
- `AttemptTimeline`：投递尝试、工具调用和验证阶段的统一时间线结构。

这些组件只接受 React 节点、纯值和回调，不依赖任何 API module 或后端 DTO。

## 页面数据流

列表页面通过 `api/modules/*` 取得数据，并把加载函数交给
`useServerPagination`。页面只负责：

1. 声明分页大小和业务列/卡片字段。
2. 管理选择项、编辑草稿和发布/重试等业务动作。
3. 把业务状态映射为公共组件可显示的值。

共享层负责：

- 拼接分页和搜索参数。
- 防止旧请求覆盖新请求。
- 统一加载、失败、空结果和重试行为。
- 通过 `api/client.ts` 处理认证、刷新和流式请求。

页面禁止直接调用 `fetch`、拼接认证头或重复实现分页状态。

## 迁移顺序

1. 先补齐 `DataTable` 的空状态、`DetailPanel`、`FormField`、`FormActions`
   和状态映射契约，并为每个组件写失败测试。
2. 迁移重复表格页：
   `JobsPage`、`ReviewQueuePage`、`EventDeliveriesPage`、`SourceBuildsPage`、
   `SourceHealthDetailPage`。
3. 迁移管理、AI、翻译、小说分析和系统设置中的重复卡片、表单和详情区。
4. 将页面引用从 `ConsoleLayout` 收敛到 `ConsolePageShell`，确认没有生产引用
   后移除兼容别名。
5. 删除迁移后无引用的旧样式和重复状态实现。

每一步都先增加一个描述目标行为的 Vitest 用例，确认测试失败，再实现最小
组件或迁移，最后运行对应页面回归和全量构建。

## 错误与可访问性

- 所有异步列表状态必须有 `aria-live="polite"` 或等效状态通知。
- 失败状态必须保留重试入口，并保持当前页面和搜索条件。
- 表格操作按钮必须有稳定的可访问名称和禁用态。
- 移动端表格必须允许横向滚动，不得挤压或遮挡关键内容。
- 状态颜色不能作为唯一语义，必须同时显示文本。

## 验收标准

- 所有已认证控制台页面使用统一页面壳；登录、全屏人工验证和独立错误流程
  保持各自布局。列表页使用统一分页/状态组件。
- 五个目标表格页不再直接声明重复的表头、行容器和边框布局。
- 通用表单和详情布局由共享组件提供，页面保留业务字段和动作。
- 前端 API 调用集中在 `api/client.ts` 与 `api/modules/*`。
- 组件契约测试、页面回归测试、`npm test -- --run` 和 `npm run build`
  全部通过。
