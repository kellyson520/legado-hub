# Legado Hub 前端中英文界面设计

## 目标

将控制台所有用户可见的固定文案统一纳入中英文国际化，首次访问默认中文，并允许用户在登录页和控制台顶部切换中文/English。选择保存到浏览器后，刷新和重新登录仍保持不变。

## 范围

- 登录页、认证恢复页、权限/错误/加载状态。
- 侧边栏、顶部栏、主题控制、分页和通用数据组件。
- 书源、健康诊断、规则引擎、AI、小说分析、翻译、操作队列、管理、系统设置等已路由页面。
- 已知后端状态码、角色、任务状态和审核状态的中文/英文显示映射。
- 业务数据（书名、书源名、模型名、URL、用户输入、后端返回的未知文本）不强行翻译。

## 不在范围内

- 后端 API 字段、日志、数据库内容和 Legado 书源规则。
- 自动翻译任意后端自由文本；未知枚举回退为原值。
- 引入第三方国际化运行时依赖。

## 方案

新增 `LanguageProvider` 和 `useLanguage`，使用内置、类型安全的 `zh-CN` / `en-US` 文案目录。文案键使用稳定的语义路径，支持 `{name}`、`{count}` 等简单插值。Provider 在应用根部包裹 `ThemeProvider`、路由和 Toast；未包裹的单元测试组件可通过默认上下文安全渲染。

语言存储键为 `legado.locale`，仅接受 `zh-CN` 和 `en-US`，无效值或首次访问回退 `zh-CN`。顶部提供文字切换按钮，当前语言使用 `aria-pressed`，登录页提供同样的切换入口。切换只更新 React 状态，不刷新页面。

页面改造遵循两条规则：固定可见文案调用 `t(key, params)`；来自接口或用户输入的动态内容保持原值。导航项不再直接保存显示文案，而保存稳定的翻译键，标题和当前路径显示统一通过 `t` 获取。

## 错误与回退

- 未找到翻译键时，开发环境返回键名并记录一次 `console.warn`，生产环境返回英文目录值，避免空白 UI。
- 后端 `code` 优先通过错误目录映射；未知错误保留后端 message，若无 message 则使用当前语言的通用失败提示。
- 状态、角色和权限名称通过目录映射；未知值原样显示。

## 测试与验收

- 语言 Provider：首次中文、合法值持久化、非法值回退、切换即时更新。
- 翻译函数：插值、状态/错误/角色映射、未知键回退。
- 登录页和控制台顶部：可见语言切换按钮、切换后文案更新、`aria` 属性正确。
- 通用分页、列表状态、导航和系统设置至少各保留一项中文和英文渲染回归测试。
- 运行完整前端 Vitest、TypeScript 构建和 `git diff --check`；构建产物部署后使用两种语言检查登录、导航、系统设置和一条列表页。
