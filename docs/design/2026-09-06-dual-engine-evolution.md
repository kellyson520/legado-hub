# 小说写源引擎与小说分析引擎双演化设计文档

## 1. 目标与愿景
本设计旨在深化并演化 LegadoHub 的两大核心引擎：
1. **小说写源引擎（Source-Writing Engine）**：从传统的简单硬编码/依赖 LLM 阅读海量 HTML，演进为**纯代码与启发式 DOM 归纳推断引擎**。从输入网页 HTML 中毫秒级自动推导目录（TOC）、正文（Content）与搜索（Search）规则；使大模型仅需在有歧义或反爬微调时调用，写源 Token 消耗降低 85% 以上，且支持一键逆向生成合规 Legado 书源。
2. **小说分析引擎（Novel Analysis Engine）**：从单次将数万字原始长文本倾倒入 LLM 提示词，演进为**代码优先多维图谱与时序索引引擎**。底层通过纯算法自动完成人物别名归一、角色重要度排序、时间轴因果链抽取、高密高潮场景识别；并通过紧凑的结构化中间表达与工具集（Overview, Character Graph, Timeline, Climax Scenes）暴露给 LLM，使单次分析 Token 消耗降低 70%~85%，同时彻底消除截断与幻觉。

## 2. 核心算法设计

### 2.1 写源引擎：启发式 DOM 模式归纳算法 (`SourceInductionEngine`)
- **目录规则归纳 (`infer_toc_rule`)**：
  - 计算全页面超链接集合并聚类：提取 `href` 路径模式与容器层级。
  - 特征加权：链接文本包含“第...章/回/节/卷”或递增数字序列者加权 +50；
  - 容器方差与密度计算：寻找具有最大正规链接密度的最小公共父容器（如 `#list dl dd a`, `.catalog-box a`）；
  - 输出 Legado 规范的 `ruleToc`: `chapterList`, `chapterName`, `chapterUrl`。
- **正文规则归纳 (`infer_content_rule`)**：
  - 基于文本标签比（Text-to-Tag Ratio）与段落密度：过滤 `nav`, `header`, `footer`, `script`, `style`, `aside`, `comment` 等噪声标签；
  - 对候选文本节点计算中文字符量与 `<p>`/`<br>` 段落密度，定位正文核心容器（如 `#content`, `.read-content`, `#chaptercontent`）；
  - 自动归纳常见广告净化规则（`replaceRule` 正则）。
- **搜索规则归纳 (`infer_search_rule`)**：
  - 自动分析 `<form>` 行为（action 路径、GET/POST 方法、输入参数名 `q`/`keyword`/`key` 等）；
  - 若提供搜索结果页，自动按列表重复元素归纳 `bookList`, `name`, `author`, `bookUrl` 选择器。
- **与 LLM 的协同模式**：
  - 算法全自动产出基准规则；
  - 若置信度低于阈值，仅将 DOM 骨架（去重后的标签树简写，约 200~500 tokens）作为工具参数供 LLM 纠偏，避免传入原始大 HTML。

### 2.2 小说分析引擎：代码优先图谱与场景挖掘 (`NovelAnalysisEngine`)
- **人物识别与别名归一算法 (`CharacterGraphExtractor`)**：
  - 停用词与动词过滤字典增强：严密剔除助词与虚词；
  - 前缀与修称模式匹配（“老X”, “小X”, “X哥”, “X总”, “X姐”）；
  - 别名聚类归一：若“小林”与“林弦”在紧密章节共现且姓氏重合，自动聚类至同一实体节点，建立别名列表；
  - 节点度数中心性与频次加权：计算全书核心主角、配角与龙套分层。
- **时间与事件因果链抽取 (`TimelineExtractor`)**：
  - 绝对时间与相对时间抽取；
  - 识别时序转折关键词（“破晓”、“深夜”、“半年后”、“突然”）；
  - 关联事件触发动作与主谓宾三元组。
- **高潮与高张力场景定位算法 (`SceneTensionDetector`)**：
  - 维护冲突/动作/悬疑情感关键词词库（如“枪”、“爆炸”、“杀”、“厉鬼”、“恐怖”、“反转”、“死亡”、“崩溃”）；
  - 采用滑动窗口（Window Size = 300 字符）计算全篇张力曲线，定位 Top-K 高冲突与悬念高潮片段。
- **结构化中间表达与轻量化 Toolset (`NovelAnalysisTools`)**：
  - 将庞杂小说文本提炼为紧凑的结构化数据包（`Digest`）：包含故事元数据、主要角色关系卡、时间节点线、核心高潮场景片段（总 token 仅约 1,500 ~ 2,500）；
  - 暴露底层快速解析工具供 LLM 按需即时查询：
    - `get_character_network`: 查询角色关联与频次；
    - `get_timeline`: 查询时序事件列表；
    - `get_climax_scenes`: 查询高能场景片段。

## 3. 架构与数据流

```
[原始小说 / 目标网站 HTML]
          │
          ▼
┌─────────────────────────────────────────────────────────┐
│              底层代码优先算法层 (Deterministic / Code)   │
│  - SourceInductionEngine: 启发式DOM树归纳与选择器生成   │
│  - CharacterGraphExtractor: 实体识别、别名聚合、关系度  │
│  - TimelineSceneDetector: 时序因果链、高潮张力场景检测 │
│  - StructuralDigestBuilder: 结构化高密压缩数据包生成   │
└──────────────────────────┬──────────────────────────────┘
                           │ 毫秒级产出结构化数据 (耗费 0 Token)
                           ▼
┌─────────────────────────────────────────────────────────┐
│               LLM 工具调用与交互层 (LLM Tools Layer)    │
│  - tool_infer_book_source (一键写源微调)               │
│  - tool_query_character_graph (角色网络)                │
│  - tool_get_novel_timeline (时序因果)                   │
│  - tool_get_climax_scenes (高潮切片)                    │
└──────────────────────────┬──────────────────────────────┘
                           │ 紧凑高密输入 (仅 1.5k~2.5k Tokens)
                           ▼
┌─────────────────────────────────────────────────────────┐
│               大模型深析输出 (High-Level Synthesis)     │
│  - 深度主题解构 / 人物弧光分析 / 规则异常自愈纠偏       │
└─────────────────────────────────────────────────────────┘
```

## 4. 效益与验收标准

1. **写源引擎**：
   - 给定标准小说目录 HTML，纯代码算法能在 50ms 内自动识别 `ruleToc` 和 `ruleContent`，准确率达 90% 以上。
   - LLM 调用辅助时，输入 prompt 不超过 800 tokens。
2. **分析引擎**：
   - 能够对《天才俱乐部》和《神秘复苏》文本快速提取准确的人物网络（剔除“不要”、“可是”等噪音词，并完成别名归一）。
   - 结构化数据包替代原始长文本输入，单次 LLM 深析输入 Token 从 10,000+ 降至 2,500 以内（**降低 75% 以上**）。
   - 提供标准工具接口供 Agent / LLM 随时查询细节。
3. **工程合规与测试**：
   - 遵循 TDD 流程，新增完整的单元测试与回归测试用例；
   - 后端全部测试通过，工作树干净。
